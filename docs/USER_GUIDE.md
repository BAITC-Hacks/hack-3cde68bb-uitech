# SupplyMind — краткое руководство пользователя

Приложение помогает рассчитать, сколько товара заказать каждому поставщику. Откройте [SupplyMind](http://127.0.0.1:5173/) при работающем локальном сервере. Это стандартный порт Docker/dev; для preview или изменённого порта используйте адрес, выведенный при запуске. Инструкция запуска — в [README](../README.md).

## 1. Выберите данные

Для знакомства нажмите **Демо-сценарии → Заказы двум поставщикам**. Программа создаст набор и выполнит расчёт на синтетических данных — переходите к шагу 4.

Для работы выберите существующий **Набор данных** либо нажмите **Загрузить данные**:

1. Укажите поставщика: **Systeme Electric** или **IEK**.
2. Выберите шесть XLSX-файлов из распакованного архива: динамика продаж, продажи по месяцам, остатки по месяцам, остаток и товары в пути, минимум / кратность закупки, сезонность.
3. Проверьте назначение каждого файла, задайте название набора и нажмите **Импортировать 6 файлов**.

Лимиты интерфейса: до 15 МБ на файл и до 39 МБ суммарно (сервер принимает multipart-запрос до 40 МБ с учётом служебных полей). Исходные файлы сохраняются без изменений.

## 2. Проверьте качество данных

Откройте **Качество данных**. Замечания показывают, каких сведений не хватает или что требует проверки. Успешная загрузка ещё не означает готовность всех товаров к расчёту.

Через **Уточнить данные** внесите подтверждённые сведения о товаре, укажите автора и причину исправления. Сохраняется новый набор, после чего нужно выполнить новый расчёт. Если нужного поля нет в редакторе, передайте замечание аналитику для подготовки исправленного набора.

Для IEK в исходном архиве нет актуального остатка: его требуется уточнить. Неизвестные остатки, даты поставок и наличие товара программа автоматически не придумывает.

## 3. Задайте параметры расчёта

Нажмите **Параметры расчёта** или **Настроить расчёт**.

| Поле | Что указать |
|---|---|
| **На начало дня** | Дату расчёта. Остатки должны соответствовать этой дате. |
| **История с** | Начальную дату анализа продаж; конечная граница — начало дня расчёта. |
| **Склад** | Склад, для которого нужен заказ. |
| **Срок поставки** | Дни от размещения заказа до получения товара. |
| **Период заказа** | Интервал между заказами: например, 7 дней — раз в неделю. |
| **Страховой запас, дни** | На сколько дополнительных дней спроса создать запас; 0 — без дополнительного запаса. Задаётся по категориям. |
| **Закупка → Разрешена** | Снимите галочку, если товары категории закупать нельзя. |
| **Сезонность** | «Из данных» — использовать загруженные коэффициенты; «Оценить по истории» — нужны минимум два полных наблюдения каждого месяца года и достаточное число дней наличия. При нехватке истории расчёт блокируется. |
| **Рост спроса** | «Задать вручную» — применить указанный процент; «Тренд по истории» — оценить изменение по минимум трём полным месяцам с достаточными данными. |
| **Изменение, %** | 0 — без поправки, 20 — увеличить прогноз на 20%, −10 — уменьшить на 10%. Это поправка ко всему прогнозу, не ежемесячный рост. |

Сроки и запас задавайте по реальным правилам компании. Числовые коды категорий сами по себе не определяют размер запаса.

Нажмите **Рассчитать рекомендации**.

## 4. Проверьте рекомендации

Используйте поиск и фильтры, просмотрите группы поставщиков. Откройте товар, чтобы увидеть объяснение количества, графики, исключённые разовые продажи и замечания.

Основа расчёта:

**Период прогноза = срок поставки + период заказа.**

**Заказ = спрос за период прогноза + страховой запас − свободный остаток − подтверждённые поставки в расчётном периоде.**

Здесь срок поставки и период заказа сначала складываются в днях, затем на этот период рассчитывается количество товара. Отрицательная потребность принимается равной нулю. Итог переводится в единицы закупки и округляется с учётом минимального заказа (MOQ) и кратности упаковки.

Пример при постоянном спросе 10 шт./день: доставка 14 дней, заказы каждые 7 дней, запас ещё на 5 дней, остаток 80 шт., ожидается подтверждённое поступление 40 шт. внутри 21-дневного горизонта. Потребность: **10 × (14 + 7 + 5) − 80 − 40 = 140 шт.**, до округления по правилам закупки. Числа приведены только для объяснения.

Если у товара статус **«Нужны данные»**, откройте его и устраните указанные причины через уточнение исходных данных. Прочерк в количестве не означает нулевую потребность. Пока есть заблокированные позиции, утвердить расчёт нельзя.

## 5. Скорректируйте и утвердите заказ

При необходимости в карточке товара заполните **Скорректировать заказ**: количество в единицах закупки и причину изменения. Нажмите **Сохранить корректировку**. Кнопка **Вернуть рекомендацию** отменяет ручную правку. Количество `0` с причиной исключает готовую позицию из CSV; для позиции «Нужны данные» такая правка недоступна.

Нажмите **Утвердить заказ**, заполните **Кто проверил заказ**, изучите и подтвердите перечисленные ограничения, затем нажмите **Подтвердить утверждение**. Утверждается весь расчёт, независимо от фильтров таблицы.

Любая последующая корректировка количества отменяет прежнее утверждение: заказ нужно проверить и утвердить повторно.

## 6. Скачайте заказ

Нажмите **Экспорт CSV**, выберите поставщика и нажмите **Скачать CSV**. Повторите для остальных поставщиков. В файл попадут только положительные количества выбранного поставщика из текущей утверждённой версии.

CSV использует UTF-8 и разделитель «;». При импорте в Excel задавайте текстовый формат для артикулов с ведущими нулями. Автоматической отправки поставщику нет; совместимость с импортом 1С пока не подтверждена.
